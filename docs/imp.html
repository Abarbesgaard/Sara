The flow of one change

One pull request breathes in and out above the Contract. Each numbered stage below runs on its own; a person only looks where the blast radius calls for it.

Write the obligation Rule 13Rule 20

Before the code, what sara must do goes into the Contract as one numbered sentence a test can prove, such as ids/A6: a blank id matches nothing. Obligations are never renumbered. A covers block names the code they are about and a surface block the commands and MCP tools their tests drive.

contract/<primitive>/README.md

Only the ids primitive is written so far. 52 contract tests in 15 files still need obligations (#316).

Make it executable Rule 20

Each contract test names the obligations it proves with #[impish::contract("ids/A6")], which fails to compile when the tag points nowhere. impish's cargo impish check fails the build when an obligation has no test, a covers or surface line names something sara doesn't have, or the published coverage is stale.

tests/contract/<primitive>.rscargo impish check

The agent sprawls until the feature shows its shape, then the same PR folds what was learned back into what exists. Parsers are checked with generated input (proptest): add tokens, dates, plan import, and 256 schema-shaped calls to every MCP tool. Their shrunk failures are kept as regression files.

Standards, enforced by machines Rule 19Rule 24

Formatting, Clippy, unused dependencies, workflow security (zizmor) and dependency policy (cargo-deny) run first. Architecture rules (archunit) keep the domain layers pointing inwards and the command slices apart. New similar code fails the PR unless it is declared in scripts/similar-code.allow, so duplication gets folded.

Mutants on the PR diff Rule 26

cargo-mutants changes every line the PR touched (+ becomes *, a ! disappears, a function returns a default) and runs the tests against each mutant. A mutant no test catches fails the PR: new code must come with a test that notices when it breaks.

Merge and release

Green merges itself Rule 27

A single CI job needs every other job and fails if any of them failed or was cancelled. Main's ruleset requires only that check, so gh pr merge --auto --squash lands a PR the moment it is green, with no human in the loop.

CIruleset: protection on main

Every green merge is a release Rule 3

A PR that changes what ships (src/, assets/, Cargo.toml, Cargo.lock) fails until it bumps the version in Cargo.toml. On merge the new version is tagged automatically, and the tag builds and publishes the release.

ci.yml (Policy)auto-tag.ymlrelease.yml

Dependabot can't bump the version, so its updates ship with the next release.

Keep it honest

Every test proves it's worth keeping Rule 26

The kill matrix runs every test against every mutant, one of 128 shards a night, and records which tests catch what. A test that catches nothing another test doesn't already catch gets an issue: delete it, or close the issue to keep it.

kill-matrix.ymlscripts/kill-matrix.shbranch: kill-matrix-data

It files issues but doesn't fail the build yet (#296).

Coverage is published Rule 29

Every CI run prints Contract coverage from contract/coverage.json in its job summary: obligations per primitive, and which commands and tools no obligation covers yet.

When a bug is found

A bug means the Contract was missing something (Rule 28). The obligation comes first and the fix comes last.

1. ObligationWrite the promise the bug broke into the Contract.
2. RedIts test fails against the unchanged code.
3. Kills the mutantThe test catches the mutant that matches the bug.
4. FixChange the code until the Contract is met.
5. Labelfix: for a bug in a release, refine: for anything else (Rule 9).

Example: generated MCP calls found that sara done "" completed a task, because a blank id matched every id. ids/A6 went in with the test a_blank_id_matches_nothing, and only then did the lookups refuse a blank id.
